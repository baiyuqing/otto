# ACP TCP in the existing serve process

Approved scope: the user requested that `otto serve` expose ACP on a separate
port and that connect use it without starting an `otto acp --attach` process.
The existing stdio ACP interface remains compatible.

- `otto serve --acp-listen HOST:PORT` opens an additional loopback TCP listener.
  HTTP and ACP share the same server's controllers, persisted history, turn
  queue, approval decisions and cancellation. ACP uses the existing relay
  mapping and dispatches against the server router in process: no internal
  HTTP socket, extra listener or child process is needed for dispatch.
- `[agent].address` selects TCP in connect; `command` selects the existing
  stdio process. They are mutually exclusive. TCP requires `token_env`;
  credentials are read from the environment, never the file.
- `OTTO_ACP_TOKEN` authenticates the serve listener. The first line is
  `Authorization: Bearer <token>\n`, then ACP's normal newline-delimited JSON-RPC
  frames. The preface is an Otto transport convention, not an ACP extension.
  Token comparisons reuse the HTTP bearer check. Authentication is bounded to
  five seconds and 4096 bytes; the listener caps connections at 64. Neither
  tokens nor incoming frames are logged. The serve token is always withheld
  from tool environments, even when an environment allowlist names it.
- ACP is scoped to serve's startup workspace. Existing HTTP workspace
  admission remains unchanged. Each connection tracks only sessions it has
  opened; memory review may access only those session controllers and reuses
  the existing human review contract.
- EOF cancels this connection's prompts and ends its protocol tasks, without
  closing shared sessions or serve. Serve shutdown closes TCP connections,
  cancels their turns and joins their workers before closing controllers.
- Connect reconnects on next use after a disconnect, applying its existing
  bounded backoff, then loads the persisted chat session. Close/Kill on the
  TCP transport only disconnects; it never terminates serve.
- The existing configuration-management HTTP client in connect is configured
  from the stdio attach command; its chat commands remain attach-only.

Acceptance: authentication rejection, bounds and loopback restriction; token
withholding/redaction; direct ACP request and reply through real serve and a
fake model provider; shared history with an HTTP client; reconnect without
history duplication; cancellation/approval/memory review; connector and server
shutdown. Existing stdio and HTTP/attach tests remain passing.
